## 🚀 Featured projects

<a href="https://github.com/anchalrajput25/RootVanta"><img src="assets/card-rootvanta.svg" width="100%" alt="Rootvanta: AI-assisted incident response. Investigates alerts across metrics, logs and traces, proposes a guarded fix with approval, checks metrics afterwards and undoes the fix if recovery fails."/></a>

**Problem:** on-call engineers lose time finding the cause of an incident, and an automated fix is only useful if something checks that it worked.<br>
**Evidence:** 88.9% correct root cause on 1,000 synthetic practice incidents (rule engine, no LLM in the loop) · 0 false "fixed" verdicts across 11 scripted verification scenarios · AC@1 0.49 on RCAEval (735 cases), level with the BARO baseline.<br>
**Limits:** benchmarks are generated by the project or run locally, not on a production cluster. Fixes cover rollback, feature-flag fallback and scaling. In development (milestone 11).<br>
[Code](https://github.com/anchalrajput25/RootVanta) · [Benchmarks](https://github.com/anchalrajput25/RootVanta#benchmarks) · [Architecture](https://github.com/anchalrajput25/RootVanta#architecture) · [Results notes](https://github.com/anchalrajput25/RootVanta/blob/main/evals/RESULTS.md) · [Demo GIF](https://github.com/anchalrajput25/RootVanta/blob/main/docs/assets/rootvanta-demo.gif)

<a href="https://insight-x-pied.vercel.app"><img src="assets/card-insightx.svg" width="100%" alt="InsightX: natural-language to SQL with hybrid table retrieval, an AST-based read-only safety gate and a trust score. 92.6% execution accuracy, 25 of 27, on a 108-table warehouse benchmark. Live demo."/></a>

**Problem:** text-to-SQL is risky when the model can pick the wrong table, write to the database or answer with numbers it made up.<br>
**Evidence:** execution accuracy 92.6% (25/27, 95% CI 76.6–97.9) on a 108-table warehouse and 75.5% on the Olist dataset · all destructive requests blocked (2/2 and 4/4) · all unanswerable questions declined (3/3 and 4/4) · 350 test functions.<br>
**Limits:** small golden sets with one run per model on free tiers. Weak on nested queries, ratios and `HAVING` on Olist. p95 latency 27–74 s.<br>
[Code](https://github.com/anchalrajput25/InsightX) · [Live demo](https://insight-x-pied.vercel.app) · [Benchmarks](https://github.com/anchalrajput25/InsightX#evaluation--benchmarks) · [Architecture](https://github.com/anchalrajput25/InsightX#system-architecture)

<a href="https://github.com/anchalrajput25/tool-utility-reliability"><img src="assets/card-research.svg" width="100%" alt="Research: do LLM hidden states show when a web-search tool call helped? Follow-up to Wu et al. 2026 on Llama-3.2-3B. Probe AUROC rose from 0.60 to 0.75 after the search result, n = 229."/></a>

**Question:** can a model's hidden states tell whether a web search actually helped it answer?<br>
**Evidence:** probe AUROC 0.60 before vs 0.75 after the search result (paired difference +0.15, 95% CI 0.06–0.24, n = 229). In 19% of forced searches (60/314) the model used a wrong argument name, so the tool returned an error.<br>
**Limits:** one model, one task and one search engine. An LLM judge was checked against a second model, not humans. Live search results drift over time.<br>
[Code](https://github.com/anchalrajput25/tool-utility-reliability) · [Report (PDF)](https://github.com/anchalrajput25/tool-utility-reliability/blob/main/report/Report_ToolUtility.pdf) · [Results](https://github.com/anchalrajput25/tool-utility-reliability/tree/main/results)
